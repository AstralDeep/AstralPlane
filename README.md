# AstralPlane

## Overview

AstralPlane is a Python-based backend middleware designed to bridge the gap between user-facing frontends (like the web-based **AstralProjection**) and sophisticated agentic AI models, particularly those implementing the Model Context Protocol (MCP).

It functions as an intelligent intermediary, facilitating communication and data flow. AstralPlane handles both standard RESTful API interactions and real-time WebSocket streams. A key feature is its ability to pass information from the backend AI that drives not only the *content* but also the *visual rendering* on the frontend. **Visual primitives**, discovered or generated by the AI models (potentially via tool calling), are relayed through AstralPlane and pushed to the frontend (like AstralProjection) for dynamic UI generation, enabling a truly **AI-driven UI**.

This backend manages connections and translates requests between the frontend client and one or more backend MCP servers or other AI/agentic models, serving as the engine powering the dynamic frontend experience.

## Key Features

* **Middleware Architecture:** Acts as a central hub connecting frontends (like AstralProjection) and AI/MCP backends.
* **Hybrid Communication:** Supports both standard RESTful APIs (for operations like authentication, project management) and WebSockets (for real-time AI interaction streams and UI updates).
* **MCP Integration:** Natively designed to interact with AI models and servers using the Model Context Protocol (MCP). Includes client logic and connection management for MCP endpoints.
* **AI-Driven UI Control:** Generates and transmits UI definitions (as nested **primitives**) and real-time updates to the frontend via WebSockets, enabling dynamic and context-aware user interfaces consistent with the AstralProjection frontend concept.
* **Real-time Data Streaming:** Leverages WebSockets for low-latency communication, sending messages like `initial_ui_state`, `primitive_content_update`, `mcp_progress`, and `tool_schemas` to the frontend.
* **Action Handling:** Receives `ui_action` messages from the frontend via WebSockets, triggering corresponding backend processes or AI interactions.
* **Authentication & Authorization:** Secures endpoints using token-based authentication.
* **Project Management:** Provides APIs to organize work or sessions into distinct projects.
* **Asynchronous Processing:** Built using FastAPI and asynchronous libraries for efficient handling of concurrent connections and I/O operations.


## How to Run
1. Create a virtual environment and install dependencies.
2. Run one (or multiple) of the servers in the ```mcp_servers``` directory.
3. Run the ```main.py``` script to start the AstralPlane server.
4. You are ready to accept connections to AstralProjection or other frontends.

## Architecture

AstralPlane employs a layered architecture:

1.  **API Layer (`app/api/`)**: Exposes REST endpoints (using FastAPI) for authentication (`auth.py`), project management (`projects.py`), and establishes WebSocket connections (`websockets.py`).
2.  **Service Layer (`app/services/`)**: Contains the core business logic.
    * `auth_service.py`: Handles user authentication logic.
    * `project_service.py`: Manages project-related operations.
    * `connection_manager.py`: Manages active WebSocket connections from frontend clients (like AstralProjection).
    * `mcp_connection_manager.py`: Manages connections (likely WebSocket or similar) to backend MCP servers/models.
    * `dataplane_manager.py`: Orchestrates the flow of data (user prompts, AI responses, visual primitives, tool schemas) between the frontend, AstralPlane, and the MCP/AI backends. Handles incoming `ui_action` messages and sends outgoing UI updates (`initial_ui_state`, `primitive_content_update`, etc.).
3.  **Repository Layer (`app/repositories/`)**: Abstracts database interactions. Uses a base repository pattern (`base.py`) with specific implementations for users (`user_repository.py`) and projects (`project_repository.py`).
4.  **Database Layer (`app/database.py`)**: Configures and manages the database connection (likely using SQLAlchemy).
5.  **Models (`app/models/schemas.py`)**: Defines data structures and validation rules using Pydantic schemas for API requests/responses and internal data handling (including the structure of UI primitives and WebSocket messages).
6.  **MCP Interaction (`app/mcp_*.py`)**: Contains specific code for communicating with MCP servers, including client implementations (`mcp_client.py`) and potentially mock servers or specific interaction patterns (`mcp_chatviewreasoning.py`, `mcp_mock_*.py`).
7.  **Configuration (`app/config.py`)**: Manages application settings, potentially loading from environment variables or configuration files.
8.  **Utilities (`app/utils/`)**: Includes helper functions and configurations like logging (`logging_config.py`, `websocket_logger.py`).

## Setup and Installation

1.  **Clone the repository:**
    Run `git clone <your-repository-url>` and then `cd astralplane-backend`.

2.  **Create and activate a virtual environment:**
    Run `python -m venv venv`. Then activate it (e.g., `source venv/bin/activate` on macOS/Linux or `venv\Scripts\activate` on Windows).

3.  **Install dependencies:**
    *(Assuming a requirements.txt file exists)*
    Run `pip install -r requirements.txt`.

4.  **Database Setup:**
    * Ensure your database server (e.g., PostgreSQL) is running.
    * Configure the database connection URL in `app/config.py` or via environment variables.
    * Run database migrations (if using Alembic):
        Example Alembic command: `alembic upgrade head`.

## Configuration

Application settings are managed in `app/config.py`. Key configurations likely include:

* `DATABASE_URL`: The connection string for the primary database.
* `SECRET_KEY`: A secret key for signing tokens and security purposes.
* `ALGORITHM`: The algorithm used for JWT token encoding (e.g., `HS256`).
* `ACCESS_TOKEN_EXPIRE_MINUTES`: Expiry time for access tokens.
* `MCP_SERVER_URLS`: Endpoint addresses for the backend MCP servers or AI models.

It is recommended to use environment variables for sensitive information like `DATABASE_URL` and `SECRET_KEY` rather than hardcoding them.

## Running the Application

Use an ASGI server like Uvicorn to run the FastAPI application. Run the command:
`uvicorn app.main:app --reload --host 0.0.0.0 --port 8000`

* `--reload`: Enables auto-reloading for development (remove in production).
* `--host 0.0.0.0`: Makes the server accessible on your network.
* `--port 8000`: Specifies the port to run on.

The application should now be running and accessible at `http://localhost:8000` (or the configured host/port). API documentation is likely available at `http://localhost:8000/docs` (Swagger UI) and `http://localhost:8000/redoc` (ReDoc).

## WebSocket Communication (with AstralProjection)

AstralPlane communicates extensively with the frontend via WebSockets to enable the dynamic, AI-driven UI:

* **Connection**: Established after successful authentication and project selection on the frontend, using the authenticated WebSocket endpoint.
* **Key Messages Sent by Backend:**
    * `initial_ui_state`: Defines the entire initial UI structure using nested primitives. Sent upon connection or when the AI decides a full UI refresh is needed.
    * `tool_schemas`: Provides schemas for tools the AI might use or reference, potentially for frontend display or validation.
    * `primitive_content_update`: Updates the content or state of specific UI primitives (e.g., appending text to `StreamingTextView`, updating `LogView`, clearing an `InputField`, adding items to `ChatViewBasic`). Specifies the `targetId` of the primitive to update.
    * `mcp_progress`: Sends progress updates from backend MCP processes or long-running tasks.
    * `mcp_notification`: General status notifications from the backend or AI agents.
    * `error`: Indicates an error occurred during backend processing, potentially displayed to the user via a frontend notification mechanism.
* **Key Messages Received from Frontend:**
    * `ui_action`: Sent when the user interacts with an actionable primitive (e.g., `Button`). Contains `actionId` (identifying the backend action to perform) and `arguments` (often derived from the state of other primitives like `InputField`, identified by `valueSourceElementIds` in the Button's config).

Tool calls made by the backend AI are a primary mechanism for generating the visual primitives sent to the frontend.

## Example MCP Server: `app/mcp_chatviewreasoning.py`

The file `app/mcp_chatviewreasoning.py` serves as a crucial reference implementation within the AstralPlane ecosystem. Its primary purpose is to demonstrate how developers can build their own **Model Context Protocol (MCP) compliant servers** capable of integrating custom AI logic, reasoning engines, or other backend processes with the AstralPlane middleware and, consequently, the AstralProjection frontend.

By studying this example, developers can grasp the necessary communication patterns, data structures (especially for UI primitives), and asynchronous handling required to create services that dynamically drive the AI-powered user interface presented by AstralProjection.

### Core Functionality

At its heart, `mcp_chatviewreasoning.py` likely implements a server that:

1.  **Listens for Connections:** Waits for AstralPlane's `MCPConnectionManager` to establish a connection (often via WebSockets or a similar persistent channel).
2.  **Receives Actions:** Processes incoming messages forwarded by AstralPlane. These messages typically originate from user interactions on the AstralProjection frontend, packaged as `ui_action` messages.
3.  **Executes Logic:** Triggers specific internal functions, AI model calls, or reasoning processes based on the received `actionId` and `arguments` within the `ui_action`.
4.  **Generates UI Updates:** Determines how the user interface in AstralProjection should look or change based on the results of its processing. This involves constructing data structures representing UI elements (primitives).
5.  **Sends Responses:** Transmits messages back to AstralPlane containing either full UI state definitions (`initial_ui_state`) or partial updates (`primitive_content_update`), as well as progress messages (`mcp_progress`) or notifications (`mcp_notification`).

The "ChatViewReasoning" name suggests its specific logic likely revolves around processing chat-like inputs, performing some reasoning or multi-step task, and displaying the results and intermediate steps in a chat-like or structured log format on the frontend.

### Interaction Flow Summary

The `mcp_chatviewreasoning.py` server fits into the overall flow like this:

1.  **User Input (AstralProjection):** User interacts (e.g., types in `InputField`, clicks `Button`).
2.  **Action Sent (AstralProjection -> AstralPlane):** Frontend sends `ui_action` message via WebSocket.
3.  **Action Forwarded (AstralPlane -> MCP Server):** AstralPlane's `DataPlaneManager` receives the `ui_action`, identifies the target project/MCP server (`mcp_chatviewreasoning`), and forwards the relevant payload via its connection managed by `MCPConnectionManager`.
4.  **Processing (MCP Server):** `mcp_chatviewreasoning.py` receives the message, calls its internal logic/AI based on `actionId`.
5.  **UI Generation (MCP Server):** Generates UI primitive data structures.
6.  **Update Sent (MCP Server -> AstralPlane):** Sends messages like `primitive_content_update` or `initial_ui_state` back to AstralPlane.
7.  **Update Relayed (AstralPlane -> AstralProjection):** AstralPlane's `DataPlaneManager` receives the UI update and relays it to the correct frontend client WebSocket connection.
8.  **UI Rendered (AstralProjection):** Frontend receives the UI update message, and its `DynamicRenderer` updates the displayed interface.

### Guidance for Developers

Developers should use `app/mcp_chatviewreasoning.py` as a template by:

* **Understanding the Required Interface:** Observe the expected incoming message formats (actions) and the required outgoing message formats (UI updates, notifications).
* **Replacing Core Logic:** Swap out the example's reasoning/AI calls with their own custom logic or model integrations.
* **Adapting UI Generation:** Modify the UI primitive generation logic to create the specific interface elements needed for their application.
* **Implementing State Management:** Add more robust state management if their application requires maintaining context across multiple user interactions.
* **Ensuring Asynchronous Compatibility:** Write their custom logic using `async`/`await` where necessary to maintain server responsiveness.
* **Following Communication Protocol:** Ensure messages sent back to AstralPlane adhere to the defined schemas (`initial_ui_state`, `primitive_content_update`, etc.).

By adapting this reference implementation, developers can effectively integrate diverse backend capabilities into the dynamic, AI-driven UI framework provided by AstralPlane and AstralProjection.
